# PRD: KFTCOneCAP C# WPF 재구현 (홈 화면 + 리더기 설정 화면)

## 1. 개요

### 1.1 배경
기존 `KFTCOneCAP`(가맹점 결제 단말 관리 프로그램)은 MFC(Win32, MSVC v143, MultiByte/CP949)로 개발되어 있다.
원본 소스: `C:\Project\MerchantSetup_OnPaintIcons_Clean_CP949\`

본 프로젝트는 이 중 **홈 화면**과 **리더기 설정 화면** 두 개를 C# WPF로 동일한 UI/UX와 동작으로 재구현하는 것을 1차 목표로 한다.

### 1.2 목표
- 기존 화면의 레이아웃, 색상, 폰트, 애니메이션, 인터랙션을 최대한 동일하게 재현
- 기존 비즈니스 로직(레지스트리 연동, 상태 전이, 검증 규칙)을 동일하게 이식
- 원본이 스텁(TODO)으로 남겨둔 부분은 동일하게 스텁으로 유지(범위 외 — 실제 시리얼 통신 구현은 본 PRD 범위에 없음)

### 1.3 비범위 (Out of Scope)
- 가맹점 설정(4탭), 가맹점 다운로드, 결제, 전표 설정, 키패드, 로그 전송 화면 — 후속 단계
- 실제 리더기 시리얼 통신 로직 구현 (원본도 TODO 스텁 상태). **2026-08-14 확정(사용자 지시)**:
  이 로직(실제 COM 포트 열거, 포트 열기 토글의 실제 하드웨어 흐름 등)은 향후 **외부 DLL 연동**
  방식으로 진행하며, 요구사항은 **별도 PRD 문서**로 새로 정의한다 — 이 PRD는 UX/UI 구현까지가
  목표. 상세: 7장 안내, `docs/ROADMAP.md` Phase 6 상단 안내.
- 설치 프로그램(Inno Setup), 자동 업데이트(updater.exe), watchdog/crash dump 등 앱 인프라 — 후속 검토

### 1.4 실행 환경 제약 (중요)
- **Windows 7(SP1)부터 지원해야 함** → 런타임은 **.NET Framework 4.8**로 확정(.NET 6/8 등 최신 .NET은 Windows 7에서 아예 실행 불가). `docs/ROADMAP.md` Phase 0 참고.
- 이로 인한 구현 제약:
  - `ApplyWhiteTitleBar` 같은 DWM 이머시브 타이틀바 API는 Windows 10 1809+ 전용 — 원본도 "미지원 OS에서는 no-op"이므로 WPF 버전도 동일하게 OS 버전 체크 후 조건부 적용
  - 최신 WinUI/Fluent 전용 컨트롤·API 사용 금지, WPF(net48) 기본 제공 범위 내에서 구현
  - `CommunityToolkit.Mvvm`은 .NET Framework 4.6.2+ 호환이라 그대로 사용 가능(확인됨)

### 1.5 참고
- 원본 소스 인코딩: CP949. WPF는 UTF-8/유니코드이므로 인코딩 이슈 없음.
- 원본 DPI 기준: 96 DPI, `MulDiv(px, dpi, 96)` 스케일링 — WPF는 자체 DPI 독립 좌표계(1 unit = 1/96 inch)를 사용하므로 아래 수치는 **96-DPI 기준 px 값을 그대로 WPF 좌표(Device-Independent Unit)로 사용**하면 된다.
- 원본은 "일반" / "컴팩트(화면 높이 ≤800px)" 두 세트의 치수를 갖는다. 아래 표는 `일반/컴팩트` 순으로 표기.
- 폰트: **Pretendard** (없으면 **Malgun Gothic**, 컴팩트 화면에서도 Malgun Gothic).

## 3. 홈 화면 (Home Screen)

### 3.1 화면 목적
앱 진입점. 4개 카드(리더기 설정/가맹점 설정/결제/전표 설정)로 하위 화면 진입, 하단에 최소화/종료 버튼, 우상단에 로그 전송/업데이트 버튼. 시스템 트레이 상주.

### 3.2 창 타이틀 / 크롬
- 타이틀바 텍스트: **"KFTCOneCAP Plus Ver 3.0.9 | 모듈 Ver 524"** (실행 스크린샷 기준 확인. 버전 번호는 빌드마다 동적으로 바뀜 — `앱버전 | 모듈버전` 형식)

- 흰색 타이틀바(Windows 11 DWM) 적용
- 초기 크기: 작업 영역에 맞춰 클램프 후 중앙 정렬. 컴팩트 모드(화면 높이 ≤800px)는 840×420(96dpi 기준) 사용

- 참고 스크린샷: `docs/screenshots/home_screen.png` (2026-08-13 실측 캡처)

### 3.3 레이아웃 (96px 기준, 일반/컴팩트)

```
margin(50/36)                                    [로그전송 버튼]
┌ 로고 [KFTCOneCAP][Plus뱃지]                       [업데이트 버튼]
│  금융결제원 차세대 결제 솔루션 v1.0.0.1
│
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐
│  │ 리더기  │ │ 가맹점  │ │  결제   │ │ 전표   │   ← 4카드, 동일 폭
│  │  설정   │ │  설정   │ │        │ │  설정   │      cardGap(18/12)
│  └────────┘ └────────┘ └────────┘ └────────┘
│ ─────────────────────────────────────────────  ← footer divider
│           [ 최소화 ]  [ 종료 ]                    ← 중앙 정렬 쌍
```

- `marginX` = 50/36, `cardGap` = 18/12, `cardVisualH` = 260/210
- 카드 4개는 `(clientWidth - marginX*2 - cardGap*3) / 4` 로 균등 폭
- 헤더 버튼(로그전송 132×36/125×32, 업데이트 205×36/180×32)은 우상단, 업데이트가 로그전송 바로 아래
- 하단 버튼(최소화/종료) 184×40/156×34, 중앙 정렬, 간격 16px

### 3.4 카드(Home Card) 상세

**정적 요소**
- 흰색 배경, 라운드 반경 20/16px
- 테두리: 기본 상태만 표시(연한 회색-블루, 알파 40 기준), 호버/눌림 시 페이드아웃되어 사라짐
- 아이콘: 46×56px 박스, 좌상단 인셋 28/22px. 배경은 연한 블루 원형/라운드 사각형(반경 12), 아이콘 자체는 파란 심볼
- 제목: 카드 하단 쪽, `CardTitleText` 색상
- 설명: 제목 아래, `SubText` 색상, 2줄, `\n`으로 줄바꿈

**인터랙션 애니메이션** (WPF: `Storyboard` + `EasingFunction`으로 구현)
- 호버: 카드가 위로 살짝(5px) 떠오르고(`liftY`), 미세 확대(scale 1→1.005), 그림자(글로우) 강해짐. `hoverProgress` 0→100을 20ms 간격(원본은 수동 타이머, WPF는 `Storyboard` duration으로 대체 가능)으로 back-ease-out
- 눌림: 카드가 아래로 밀리고(`pushY` 6px) 살짝 축소(scale -0.04), 배경이 연한 블루(`CardFillPressed`)로 보간, 테두리 사라짐. 아이콘 배경은 진한 블루(`Blue500`)로, 아이콘 글리프는 흰색에 가깝게 반전
- 호버 시 글로우: 카드 주변에 블러된 그림자(반투명 남색) — WPF에서는 `DropShadowEffect` 또는 다중 `Border` 레이어로 근사
- 클릭 시: 눌림 애니메이션이 어느 정도(진행률 30% 이하로) 풀릴 때까지 대기한 뒤 모달 오픈 → WPF에서는 클릭 즉시 `ShowDialog()` 호출 전 짧은 딜레이(약 16ms×N) 또는 `Dispatcher.BeginInvoke`로 근사 재현

### 4.8 포트 열기 토글 (리더기1 전용)

1. 토글 클릭 → 즉시 이전 상태로 되돌린 뒤(시각적 revert) 확인창 표시: "포트를 여시겠습니까?"(켤 때) / "포트를 닫으시겠습니까?"(끌 때)
   - ⚠️ 원본 코드 주석상 이 문구는 영문 placeholder이며 정식 한글 문구로 교체 예정이었음 — WPF 구현 시 정식 한글 문구 확정 필요 (PM 확인 필요)
2. 확인(Yes) 시: 토글에 로딩 스피너 표시, 리더기1 카드 전체 비활성화, 백그라운드 작업 시작(원본은 2.5초 딜레이 후 항상 성공 처리 — 실제 포트 개폐 미구현)
3. 10초 타임아웃: 응답 없으면 실패 처리
4. 완료 후:
   - 실패 시 토글 원복
   - 성공 & 켜짐 상태 & `INTERLOCK != TRANSINFO_AOP`: **리더기2를 강제로 "미사용"으로 설정하고 비활성화** (단일 포트 하드웨어 인터락 — 리더기1 상시 연결 중엔 리더기2 사용 불가)
   - 성공 & 꺼짐 상태: 리더기2 활성화 상태 재평가
   - 레지스트리 `SERIALPORT\PORT_ALWAYSOPEN` 저장 — **주의: 값이 반전 인코딩됨**: `"0"`=켜짐, `"1"`=꺼짐(기본값)
   - 완료 후 확인 안내창 표시("확인")
5. 포트가 열린 상태에서는 해당 COM포트 콤보 변경 불가 — 변경 시도 시 경고: "포트가 열려 있는 상태에서는 포트를 변경할 수 없습니다.\n포트 열기를 먼저 해제하세요."
6. 정상적으로 포트 변경 성공 시 안내 토스트: "리더기 {N}번 포트가 변경되었습니다."

### 4.9 멀티패드 토글 (리더기1/2 공통)

### 4.11 AOP(인터락) 제약 로직

레지스트리 `SERIALPORT\INTERLOCK` 값에 따라:

| INTERLOCK 값 | 제약 |
|---|---|
| `AOP` | 리더기2 전체 비활성화(콤보+모든 버튼+토글). 리더기1의 초기화/업데이트/포트열기토글 비활성화(콤보·상태체크·키다운로드·무결성체크는 사용 가능) |
| `TRANSINFO_AOP` | 리더기2의 초기화/업데이트만 비활성화(나머지 사용 가능). 양쪽 카드에 AOP 뱃지 표시. **확인(OK) 시 검증**: 리더기1·2 COM포트가 둘 다 "미사용"이 아니어야 함 — 위반 시 저장 차단 + 경고: "멀티패드(KFTC+AOP) 모드에서는\n리더기1과 리더기2의 포트를 모두 지정해야 합니다." |
| 그 외 | 제약 없음 |

이 제약은 화면 최초 로드 시, 콤보 변경 시, 각 로딩 작업 완료 시마다 재적용된다.

### 4.12 확인(OK) / 취소(Cancel)

**확인**:
1. TRANSINFO_AOP 검증 통과 확인
2. 레지스트리 저장: `COMPORT1_FIELD`/`COMPORT2_FIELD`(콤보 텍스트 그대로, 예: "COM 01" 또는 "미사용"), `MULTIPAD1_FIELD`/`MULTIPAD2_FIELD`(반전 인코딩)
3. 다이얼로그 닫힘(OK)

**취소**:
1. 열려있는 팝오버 닫기
2. 변경사항 확인 — 추적 대상: COM포트1/2 선택값, 멀티패드1/2 토글값 (포트열기 토글은 제외)
3. 변경사항 있으면 확인창: "변경된 내용이 있습니다.저장하지 않고 종료하시겠습니까?" (Yes/No) — No 선택 시 창 유지
4. Yes 또는 변경사항 없으면 다이얼로그 닫힘(Cancel)

### 4.13 COM 포트 목록 구성

- 시스템에서 실제 사용 가능한 COM 포트를 열거(원본: 레지스트리 `HKLM\Hardware\DeviceMap\SerialComm`; WPF: `System.IO.Ports.SerialPort.GetPortNames()` 사용 가능)
- 콤보 첫 항목은 항상 **"미사용"**, 이후 `"COM %02d"` 형식으로 정렬 표시
- 저장된 포트가 현재 열거 목록에 없으면 `"<port>(사용불가)"` 형태로 추가하여 선택 상태 유지 (조용히 버리지 않음)

> - 이 WPF 프로젝트(`KFTCTaxGiroCAP`)는 원본과 **레지스트리를 공유하지 않고 별도 앱 이름(`KFTCTaxGiroCAP`)으로 저장**하기로 확정 — PRD 6장 미확정 사항 #1("레지스트리 공유 여부")이 이 결정으로 해소됨.
> - 섹션명은 원본과 동일하게 `"SERIALPORT"`(`common.h`의 `SERIAL_PORT_SECTION` 매크로) 유지. 아래 표의 `root: KFTC_VAN\KFTCTaxGiroCAP\SERIALPORT`는 이 전체 경로의 축약 표기.

| 레지스트리 키 (root: `HKCU\Software\KFTC_VAN\KFTCTaxGiroCAP\SERIALPORT`) | 의미 | 인코딩 |
|---|---|---|
| `COMPORT1_FIELD` | 리더기1 COM 포트 | 문자열 그대로 ("COM 01", "미사용" 등) |
| `COMPORT2_FIELD` | 리더기2 COM 포트 | 상동 |
| `PORT_ALWAYSOPEN` | 포트 상시열림(리더기1) | **반전**: "0"=켜짐, "1"=꺼짐(기본) |
| `MULTIPAD1_FIELD` | 리더기1 멀티패드 | **반전**: "0"=켜짐, "1"=꺼짐(기본) |
| `MULTIPAD2_FIELD` | 리더기2 멀티패드 | **반전**: "0"=켜짐, "1"=꺼짐(기본) |
| `INTERLOCK` | 인터락 모드 | "NORMAL" / "AOP" / "TRANSINFO_AOP" |

> WPF 구현체는 `Microsoft.Win32.Registry`로 위 경로에 직접 읽고 쓴다(원본과 레지스트리를 공유하지 않기로 확정됐으므로 마이그레이션/병행 운영 이슈 없음).
