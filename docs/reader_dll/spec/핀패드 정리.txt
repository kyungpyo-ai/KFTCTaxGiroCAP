##핀패드 제어 기능 추가 
1. 리더기 SPEC과 별도로 존재하는 PINPAD-20251021 SPEC문서 기반의 시리얼통신 기능 추가 
※ 리더기 SPEC과 주요 차이점 
 - 요청에 대한 ACK 응답 존재
 - 전문 길이 타입이 1 byte  (리더기는 2byte)

2. 기본적인 통신방식은 requset-callback 방식 그대로 사용 
 - dll 사용자 입장에서는 기존 리더기 제어와 똑같은 방식 및 전문형식으로 요청 및 응답받도록 구현 필요

3. 핀패드 SPEC은 특정 기능을 수행하기위해서는 여러개의 명령어를 요청해야되는 조합 존재. 
 3.1 dll 사용자가 TPIN SPEC문서를 보고 조합을 예상하기는 어려우므로 DLL단에서 조합대로 명령어 수행 필요
      => 즉 핀패드 관련해서는 리더기때와 다르게 별도로 dll 사용자가 요청할 SPEC 사양 만들기 필요
 3.2 조합이 필요없는 명령어
  - 핀패드 초기화
 3.1. 조합이 필요한 기능 
  - 순차적으로 수행되어야하는 명령어의 집합
ex)
번호 입력시에는 아래의 명령어가 세트로 차례대로 수행되어야됨
0xf1 0x03 (Initialize parameters)
0xf3 0x00 (Customer Display)
0xf3 0x00 (Customer Display)
0xf7 0x00 (Pin Request)

=====조합 기능 4개======

1.비밀번호 입력, 2.번호 입력, 3.DES 암호화, 4.SEED 암호화

====동일 로직 구간=========
초기화
0xf1 0x03

customer display: 핀패드 디스플레이에 보여질 문구 명령어
0xf3 0x00 0x00 ~~
0xf3 0x01 0x00 ~~

pin length : 입력받을 핀 길이 (핀길이는 요청 전문에서 받는게 좋음)
1.0xf1 0x02 0x06 (ex : 6자리)
2.0xf1 0x02 0x
3.0xf1 0x02 0x
4.0xf1 0x02 0x
=======================

pin request
1. 0xf7 0x00 0x00     
2. 0xf7 0x00 0x02   
3. 0xf7 0x04 0x00 0x00 (요청받은 8byte : working key) + (요청받은 8byte : 카드번호 ACN)  
4. 0xf7 0x07 0x00 (요청받은 12byte).    


4. 즉 DLL 사용자에게는 핀패드 초기화, 비밀번호 핀입력, 번호 핀입력, DES 암호화 핀입력, SEED 암호화 핀입력 4개의 명령어 존재.
- PINPAD-20251021 SPEC 기준
  : 핀패드 초기화 		0xf1 0x03
  : 비밀번호 핀입력		0xf7 0x00 0x00    
  : 번호 핀입력		0xf7 0x00 0x02
  : DES 암호화 핀입력	0xf7 0x04 0x00      
  : SEED 암호화 핀입력	0xf7 0x07 0x00
